# Public Roadmap

This roadmap describes direction rather than delivery dates. A capability becomes a public claim only after implementation and evidence satisfy the conformance policy.

## Now: Close the Beta 3 Acceptance Gate

- complete package-exact Oxygen acceptance across supported authoring tasks
- close active editor-state, validation-scope, and repository-path findings
- finish production-shaped browser and administrator acceptance
- retain zero-skip evidence and exact package provenance
- publish current beta limitations with every evaluation build

## Next: Design-Partner Beta

- onboard named evaluation teams using real DITA corpora
- validate hosted identity-provider configurations
- exercise migration from sanitized AEM Guides, Oxygen, and Git exports
- measure graph, validation, search, import, and publishing behavior at representative scale
- convert evaluation findings into versioned conformance fixtures
- verify deployment and recovery runbooks outside the development environment

## Later: General-Availability Readiness

- deepen specialization-aware processing
- expand subject-scheme and filtering behavior
- add editor integrations through the public authoring contract
- publish richer release-diff and rebuild verification
- complete independent security and operational readiness work appropriate to the deployment model
- evaluate a separate DITA 2.0 preview lane without weakening DITA 1.3 claims

## Promotion Rule

Planned behavior is not promoted to claimed behavior until it has:

1. executable API or service coverage
2. representative fixtures
3. negative tests
4. versioned evidence
5. an updated public conformance statement
