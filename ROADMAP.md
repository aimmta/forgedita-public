# Public Roadmap

This roadmap describes direction rather than delivery dates. A capability becomes a public claim only after implementation and evidence satisfy the conformance policy.

## Now: Establish the MVP Contract

- stabilize native repository and revision behavior
- expand authoring API coverage
- validate semantic-registry and graph contracts
- strengthen baseline and release evidence
- maintain explicit capability discovery
- grow negative and interoperability fixtures

## Next: Production Boundaries

- move expensive validation and publishing work behind job boundaries
- isolate tenant publishing runtimes
- package the Oxygen add-on and framework delivery flow
- add durable job cancellation and retry behavior
- harden object storage, secrets, audit, and service-account paths
- expand search across taxonomy, graph, baseline, and release state

## Later: Broader Interoperability

- deepen specialization-aware processing
- expand subject-scheme and filtering behavior
- add editor integrations through the public authoring contract
- publish richer release-diff and rebuild verification
- evaluate a separate DITA 2.0 preview lane without weakening DITA 1.3 claims

## Promotion Rule

Planned behavior is not promoted to claimed behavior until it has:

1. executable API or service coverage
2. representative fixtures
3. negative tests
4. versioned evidence
5. an updated public conformance statement
